# Phase 6 architecture decisions

Recorded before implementation, after inspecting the Phase 1–5 reports, roadmap, migrations, application services, API and baseline checks.

1. **Authority:** `rules.db` and mechanical `Characters`/`Encounters` stay authoritative for D&D rules and HP. A separate campaign-owned narrative snapshot is authoritative for current NPC, location, faction, relationship, fact, knowledge and quest state. NPCs may link to a mechanical character ID, but never duplicate its statistics. No mechanical event automatically changes narrative state.
2. **Storage:** one `WorldStates` row per campaign stores a bounded, versioned JSON aggregate with stable entity GUIDs. It has a campaign foreign key and optimistic revision. This makes a consequence batch, its event rows, and the campaign-clock read set one SQLite transaction. Internal references are validated in the domain/application rather than represented as cross-table FKs; dedicated entity tables and indexes can follow when world-size/query needs justify them. This is a deliberate small-campaign tradeoff, not event sourcing.
3. **Commands:** typed world changes use an expected world revision, explicit cause and one or more operations. Every operation validates references and transitions against the evolving candidate snapshot; only the fully validated result is saved. The existing `X-Operation-Id` middleware wraps every new mutation, giving exact request replay across restart.
4. **Time:** world events carry the existing campaign `GameSeconds` and UTC audit time. The world store also advances the campaign revision without changing game seconds to detect concurrent time changes. No separate world clock or automatic schedules are introduced.
5. **Visibility:** ordinary player reads are an allowlist projection: public/discovered NPCs, locations, factions, quests and public facts only. They contain no private NPC fields, secret facts or knowledge records. DM views and mutations are exposed only to loopback callers of the local development API. A caller-supplied role or character ID is never an authorization boundary; remote use needs authenticated authorization in a later phase.
6. **Beliefs:** facts are campaign truth; knowledge records belong to NPCs, factions or mechanical characters and may contain a contradictory belief value. Knowledge never rewrites truth. Secret disclosure is an explicit audited operation.
7. **Scope:** a typed JSON aggregate and explicit transitions establish a playable narrative state foundation. No lore ingestion, AI, MCP, automated consequence inference, spatial simulation or automatic mechanical rewards are included.
