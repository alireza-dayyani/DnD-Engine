# Phase 6 report — narrative world foundation

Phase 6 adds a persistent, explicit campaign world for future DM tools. The existing rules and mechanical projections remain authoritative for dice, HP, combat, spells, items and XP. Narrative NPCs can exist without a stat block and can optionally link to a same-campaign mechanical character. Combat events do not automatically kill NPCs, change allegiance or progress quests; a DM must submit those consequences.

## Architecture and entity model

The [decisions record](PHASE6_DECISIONS.md) was written after the repository audit and baseline checks, before implementation. `WorldState` is a campaign-owned aggregate containing stable GUIDs for NPCs, hierarchical locations, factions/memberships, directional relationships, structured world facts, holder-specific knowledge, quests and objectives. `campaign.db.WorldStates` stores the revisioned JSON snapshot with a campaign foreign key and revision constraint. This is one bounded small-campaign write aggregate, not a new rules pack or a full event-sourced system. All internal references, hierarchy levels/cycles, duplicate identities and quest dependency cycles are checked in the application layer. Dedicated relational child tables and indexes are deferred until actual world-size or query requirements justify them.

`WorldService` applies 1–50 typed changes against an expected world revision and an explicit cause. Changes are validated against the evolving candidate state, then snapshot, campaign revision and audit events commit together through `SqliteWorldStore`. The campaign revision write guards the Phase 4 `GameSeconds` read: a concurrent clock change makes the world command conflict rather than record stale time. The world command itself never advances time. An `X-Operation-Id` claim and original successful response are committed by the Phase 5 middleware in the same transaction, so identical retries replay exactly after a timeout or restart. No failed batch leaves a partial world or event history.

NPCs store authored public/private information, appearance, background, personality, motivations, fears, goals, status and location. Locations follow World → Region → Settlement → District → Building → Room with explicit discovered state and optional controlling faction. Factions have leadership, headquarters, status, goals, optional authored influence/resources/allies/enemies and separate memberships. Relationships point from one NPC, faction or mechanical character to another and retain six distinct −5..5 dimensions plus a label/note; the reverse direction is independent.

World facts are structured subject/predicate/object truth with source and Public/Private/Secret visibility. Knowledge records identify an NPC, faction or mechanical-character holder, a fact, Known/Suspected/Believed status, confidence, an optional contradictory belief, acquisition game time and source. A belief never overwrites world truth. A secret cannot be made public through ordinary fact update; `DiscloseSecret` is a distinct audited change. Quests retain Unknown → Discovered → Active → Completed/Failed/Abandoned transitions, objectives and prerequisite graphs, related world entities, optional game-time deadlines and authored reward/consequence text. Objective progress and quest completion are explicit. Narrative rewards do not award mechanical XP or inventory.

## Queries, API and trust

[World API](WORLD_API.md) documents the typed single-entity and atomic batch operations. `GET /campaigns/{id}/world` is an allowlisted player projection: it contains discovered locations, public NPC information, public faction identity/status, public facts without provenance and public discovered quests without reward/consequence fields. It omits private NPC fields, faction resources/goals, secret/private facts and all knowledge records. The existing `/campaigns/{id}/events` route now excludes narrative events because their before/after payloads may carry secrets; `/dm/campaigns/{id}/world/events` retains their full audit history.

Full state, individual DM reads, holder knowledge and mutations live under `/dm/campaigns/{id}/world` and reject non-loopback remote addresses. This is **not authentication**: any process or user able to make a loopback request on the host can reach the DM API. The development server must remain local; a remotely exposed listener or reverse proxy requires real principals, per-campaign permissions and holder-specific authorization before any DM or knowledge route can be exposed. The player-safe read does not accept a caller-claimed role or character ID as authority. The API returns typed contracts, not EF rows or raw SQL.

World events include `NPCIntroduced`, `NPCStatusChanged`, `NPCMoved`, faction/location/membership and relationship changes, fact establishment/change/disclosure, knowledge acquisition and quest start/progress/completion/failure. Their payloads include relevant before/after state, explicit cause, world revision and authoritative campaign game time; the existing event sequence and UTC audit timestamp remain. Current state is authoritative; events explain how it changed. Phase 1–5 mechanical event payloads are unchanged.

## Limits and recommended Phase 7 scope

This is a bounded, authored world, not a simulator. There are no AI calls, MCP server, Forgotten Realms ingestion, autonomous faction/NPC activity, procedural generation, maps, travel/pathfinding, economy, remote authentication or graphical UI. Discoverability and public visibility are author decisions; marking a description public publishes it. The player projection deliberately has no private character-knowledge view until identity can be authenticated. Internal world references live inside a JSON aggregate rather than relational child FKs, and full-state reads/validation suit small campaigns rather than large-scale search. There is no automatic deadline enforcement, narrative time advance, reward conversion or mechanical-to-narrative inference.

A separately approved Phase 7 should first establish authenticated DM/player principals and per-campaign, per-holder authorization for remote/MCP tools, then add a sourced lore reference boundary. A small authored consequence/playtest slice can evaluate whether the current world commands are sufficient before expanding storage, autonomous behavior or content. **Phase 7 has not begun.**
